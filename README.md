## 문제

고객이 온라인에서 담아둔 제품이 매장에 없을 때, 응대는 "비슷한 거 보여드릴까요" 또는 "재고 확인해 볼게요"로 끝난다. **고객이 애초에 왜 그 제품을 골랐는지**는 반영되지 않는다. 정확한 디자인 때문인지, 소재를 실물로 보고 싶은 건지, 오늘 당장 필요한 건지에 따라 답이 달라져야 한다.

Segue 는 그 "왜"를 CA 가 짧은 대화로 끌어내고, 구조화된 조건을 재고·제품 속성과 대조해 **다음 행동 하나만** 제안한다.

---

## 파이프라인

```
고객 발화(자연어)
   │
   ▼
AI ①  의도 구조화 ── 자연어 → 고정 어휘 19속성 조건
   │
   ▼
   조건 충분? ── 부족 ──▶ AI ②  보충 질문 1회 ──┐
   │ 충분                                       │
   ▼                                            │
규칙 엔진  제품 속성 · 재고 대조  ◀──────────────┘
   │
   ▼
결과 4가지 중 하나 확정
   │
   ▼
AI ③  확정된 근거로 설명문 생성 → Last Intent Card
```

**AI 호출 3회 중 "무엇을 추천할지" 묻는 단계는 없다.** 결정은 전적으로 규칙 엔진이 하고, AI ③ 은 확정된 결과를 문장으로 옮길 뿐이다. 브랜드 금지어와 조건 환각은 백엔드에서 한 번 더 검증한다.

AI 가 맡는 것은 규칙으로 하기 어려운 세 가지뿐이다 — 자연어를 판단 가능한 조건으로 변환, 부족한 조건에 대한 질문 생성, 매번 다른 조건 조합의 문장화. CA 가 19속성을 폼으로 채우는 대안은 상담이 아니라 설문이 된다.

### 판단 우선순위 (코드 고정)

> ① 필수 조건 → ② 구매 시급성 → ③ 실물 확인 필요 → ④ 확보 경로(대기·타 매장) → ⑤ 선호 조건

- 필수 조건은 **전부 일치해야 통과**. 부분 일치를 허용하면 잘못 추출된 조건만이 아니라 제대로 추출된 조건까지 함께 느슨해진다.
- AI 과추출은 엔진 완화가 아니라 **CA 의 조건 확인·수정 단계**에서 막는다.
- 언급되지 않은 항목은 비워 둔다. (개발 중 "거절하지 않았으면 대기 가능"으로 기본값을 준 탓에 결과가 잘못 갈린 적이 있어 프롬프트를 수정함)
- 재고는 수량이 아니라 **보유 여부**로 판단. `confirmed`/`checked_at` 을 함께 저장해 미확인·노후 재고는 확정 경로로 쓰지 않는다.

### 네 가지 결과

| 결과 | 조건 | 다음 행동 |
| --- | --- | --- |
| **정확한 제품 확인** | 원제품에만 성립하는 조건 + 대기·타 매장 가능 | 타 매장 확인 요청 |
| **비교 체험 제품** | 실물 확인 요소가 매장 내 제품에 존재 | 이 제품 확인하기 |
| **오늘 구매 가능** | 당일 구매 조건 + 확인된 매장 재고 | 이 제품 확인하기 |
| **추가 상담** | 조건 불분명 또는 확보 경로 없음 | 조건 다시 확인하기 |

후보가 없으면 무리해서 추천하지 않고 추가 상담으로 돌린다.

## 로컬 실행

**요구사항** — Java 21, MySQL 8.0, OpenAI API 키

```bash
# utf8mb4 아니면 한글 제품명이 깨진다
mysql -e "CREATE DATABASE segue CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

cp .env.example .env    # DB 접속 정보 · OPENAI_API_KEY
./mvnw spring-boot:run  # DataLoader 가 MCM 제품 12개 + SKU·속성·재고·계정 자동 주입
curl http://localhost:8080/api/products
```

재기동해도 ID 가 바뀌거나 중복이 생기지 않는다.

## 알려진 한계

MVP 범위를 의도적으로 여기까지 잡았고, 다음 단계는 GitHub 이슈(P2)로 정의해 두었다.

- **토큰 기반 인가 미구현.** 로그인은 있으나 세션·토큰 미발급이라 `customerId` 로 조회 경로 접근이 가능하다. 변경 경로는 현재 비밀번호 확인으로 방어. 고객·직원 양쪽 인증을 함께 설계해야 하는 범위라 분리했다.
- **동의 철회 시 데이터 처리.** 철회 시 조회는 즉시 차단하나 저장된 상담 결과는 파기하지 않는다. 운영에는 보관 기간 정책과 동의 이력 감사 로그가 필요하다.
- **`ddl-auto=update`.** 개발 속도용. 운영 전환 시 마이그레이션 도구로 교체.
- **배포 계정 분리 미적용.** 현재 배포는 root SSH 로그인에 의존한다. `/var/www/segue` 쓰기 권한만 가진 전용 계정으로 분리하는 것이 맞다.
- **AI 응답 시간 7~8초** (보충 질문 포함). 스트리밍·조건 캐싱으로 단축 여지.
